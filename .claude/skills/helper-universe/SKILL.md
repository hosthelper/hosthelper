# 헬퍼유니버스 — 사업체·브랜드 메모리

> 최종 확인: 2026-08-07. 출처는 대표 직접 확인 + 이 저장소 + 공개 사이트.
> 운영 문서 전문: [`docs/AI_COMPANY_OS.md`](../../../docs/AI_COMPANY_OS.md) · 부서별 실행 프롬프트: [`docs/prompts/company-os/`](../../../docs/prompts/company-os/README.md)

## 1. 사업체

- **운영 주체**: 호스트헬퍼 (단일 사업자, 간이과세). 대표 김태욱. 서울 동대문구. 개업 2020-04-27.
- 사업자등록번호와 소재지 상세는 `docs/BUSINESS_ENTITY.md`에 있습니다. **번호를 프롬프트 본문이나 산출물에 적지 마세요** — 필요하면 그 문서를 참조하라고만 씁니다.
- 브랜드는 9개지만 **법인은 하나**입니다. 재무는 브랜드별 손익이 아니라 하나의 현금표로 봅니다.
- 예외: **BGN은 비영리 재단**이라 별도 법인격이 필요할 수 있습니다. 확인 전입니다.

| **BGN** | 비영리 재단. 헬퍼유니버스로 얻은 **순수익의 10%** 를 불우이웃 지원에. 재무상 **매출이 아니라 기부 지출** |

### 회원 생애주기

```
유니 인지 → 헬퍼아카데미 학습 → 공실헬퍼 인수 → 호스트헬퍼 청소 운영
                                              → 하우스헬퍼·넥스트헬퍼 물품 조달 → 라이프헬퍼 확장
```

12개월 비전은 이 사슬 전체를 **인지 → 가입 → 결제**로 끊김 없이 통과시키는 것입니다.
**수익 브랜드 6개를 동시에 밀지 마세요** — 사슬에서 가장 약한 고리 하나에 우선순위를 몰아야 합니다.

## 3. 아직 확정되지 않은 것 — 단정하지 마세요

1. **하우스헬퍼 ↔ 넥스트헬퍼 경계** — 둘 다 물품 상거래입니다. B2C 판매/B2B 공급으로 나뉘는지, 같은 상품을 파는지, 재고·정산을 함께 쓰는지 미확정.
2. **라이프헬퍼 ↔ 호스트헬퍼 공급 중복** — 공간 보유자와 숙소 호스트를 각각 모집합니다. 같은 사람에게 두 브랜드가 접근 중일 수 있습니다.
3. **헬퍼아카데미 상세** — 강의 형태·기간·가격·플랫폼 미확정.
4. **브랜드별 30일 목표 숫자** — 전부 빈칸입니다.

이것들을 채우려면 [`docs/prompts/company-os/00-brand-intake.md`](../../../docs/prompts/company-os/00-brand-intake.md)를 씁니다.

## 4. 가드레일 — 위반하면 산출물 폐기

### 전 브랜드 공통

- 확인되지 않은 수치·후기·사례를 만들지 않습니다. 모르면 `확인 불가`.
- 수익·법률 단정 금지. 권리금·전대·외국인관광도시민박업 요건은 "확인이 필요하다"를 붙입니다.
- 환불·법률·개인정보 판단은 AI가 확정하지 않고 사람 결정 항목으로 분리합니다.
- **이모지 금지.** 강조는 `·` `—` 로.
- 사업자등록번호·API 키·개인 연락처를 산출물에 넣지 않습니다.
- 운영·사업·UI 텍스트는 한국어 우선.

### 브랜드별

| 브랜드 | 하면 안 되는 것 | 이유 |
|---|---|---|
| **공실헬퍼** | 자기지칭 "중개" 워딩 | 공인중개사법. **공인중개사 연결**이라고 씁니다 |
| **라이프헬퍼** | 의학적 효능·회복 촉진·치료 효과 주장. 병원명·의료진을 계약 없이 제휴처럼 표기. 이용자 시술 내역·건강 상태를 콘텐츠에 사용 | 의료 인접 영역 광고 규제 + 건강 정보는 민감정보. "회복기에 머무는 공간"까지만 |
| **하우스헬퍼** | 제품 효능·성능 과장. 화장품·비누·방향제류 효능 문구 | 전자상거래법 + 화장품 표시광고 규제. 청약철회 기간과 반품 조건은 고지 |

| **넥스트헬퍼** | 발급 근거 없는 "공인인증마크" 표기 | 표시광고법. 어느 기관의 무슨 인증인지 명시 못 하면 쓰지 않습니다 |
| **BGN** | "순수익 10% 기부"를 대외 약속으로 고지 | 별도 법인격·기부금 세무 처리 확인 전 |

## 5. 숫자가 어디서 나오는가

| 지표 | 계측 경로 |
|---|---|
| 인지 (4채널 도달) | mirra `post_list` · `analytics_account_insights` — `uni` 스킬 §8 |
| 가입 (리드) | `apps/changup-site/s/index.html` → Supabase Edge Function `changup-leads` → `BuyerLead` 테이블 |
| 상담 | `BuyerLead.status` — `NEW → CONTACTED → MEETING_SET → CLOSED`. 스키마는 `packages/shared/src/schemas/changup.ts` |

**주의**: `apps/changup`의 `/ops` 대시보드는 NestJS/Postgres를 보므로 위 Supabase 리드를 **보지 못합니다.** 가입·상담 숫자는 Supabase 대시보드에서 확인합니다.
`BuyerLead` 스키마는 **공실헬퍼 설문 전용**입니다. 다른 브랜드에 그대로 적용하지 마세요.
