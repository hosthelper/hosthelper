# 부서별 복붙 프롬프트 — 헬퍼유니버스 AI 회사 OS

> 운영 체계 본문은 [`docs/AI_COMPANY_OS.md`](../../AI_COMPANY_OS.md)입니다. 이 디렉토리는 **실행용 프롬프트**만 담습니다.

## 쓰는 법 (3단계)

| 단계 | 할 일 |
|---|---|
| **01 · EDIT** | 프롬프트 안 `[대괄호]` 부분을 내 정보로 바꿉니다 |
| **02 · COPY** | `[입력]`부터 `[규칙]` 끝까지 통째로 복사합니다 |
| **03 · RUN** | Claude Code(또는 claude.ai)에 붙여넣고 실행합니다 |

## 순서

```
00 브랜드 인테이크  ← 최초 1회, 브랜드 정의가 비어 있을 때
        ↓
01 대표실           ← 매달 1회, 우선순위와 부서별 첫 업무를 뽑는다
        ↓
02 마케팅 · 06 개발  ← 제작
        ↓
03 영업             ← 판매
        ↓
04 고객지원         ← 응대
        ↓
07 운영             ← 자동화
        ↓
05 재무 + 01 대표실  ← 유지 / 중단 / 확대 결정
```

각 단계는 **앞 단계 결과물을 요약하지 말고 그대로** 다음 프롬프트의 `[입력]`에 붙여넣습니다.

## 공통 규칙 (모든 프롬프트에 이미 포함됨)

- 확인되지 않은 수치·후기·사례를 만들지 않습니다. 모르면 `확인 불가`.
- 수익·법률 단정 금지. 권리금·전대·외국인관광도시민박업 요건은 "확인이 필요하다"를 붙입니다.
- 자기지칭 "중개" 워딩 금지 — 공실헬퍼는 **공인중개사 연결**입니다.
- 이모지 금지. 강조는 `·` `—` 로.
- 사업자등록번호·API 키·개인 연락처를 프롬프트 본문에 넣지 않습니다.

전체 가드레일은 [`docs/AI_COMPANY_OS.md` §7](../../AI_COMPANY_OS.md#7-가드레일)을 보세요.

각 프롬프트의 `[출력]` 절은 **필드 목록** 형태로 적혀 있어 zod 스키마로 그대로 번역됩니다.
`packages/ai/src/dispute.ts`의 `DisputeOutputSchema`가 참고 사례입니다. 자세한 규칙은
[`docs/AI_COMPANY_OS.md` §8](../../AI_COMPANY_OS.md#8-이-문서를-코드로-옮길-때).
