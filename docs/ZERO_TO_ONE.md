# 🎯 제로투원 직군 체계 — 사업체별 역할 설계

> 출처 프레임: **ZERO TO ONE (Lilybom) 1주차 OT**.
> 「사업 = 나(BRAND) ∩ 고객(CUSTOMER)의 교집합」이며, 그 교집합을 만드는 조직은
> **제공자(상품개발팀)** 와 **전달자(마케팅팀)** 두 축으로 나뉜다.

## 왜 이 체계인가 — Level 05로 가기 위해

| Level | 명칭 | 특징 |
|---|---|---|
| 01 | 지극히 평범한 개인 | 경험 자산화를 아직 못함 |
| 02 | 창작자 | 성향·경험 중 내세울 것 시도(시행착오) |
| 03 | 제공자(프레임워크 개발자) | 나만의 노하우·기술 → 같은 효과 제공 가능 |
| 04 | 운영자 | 내부/외부 운영으로 나뉨 — **대표 없이 안 되는 구조** |
| **05** | **시스템화(시스템 설계자)** | **위임·대행·AI 자동화 + 안정적 매출 흐름** |

**실패하지 않는 두 가지 조건**
1. **대표가 알아야 한다** — AI가 발달할수록 대표의 **판단력**이 중요해진다. 대표는 결국 **헤드**의 역할.
2. **대표 없이도 돌아가는 시스템** — 대표 이해 없이 만든 시스템은 허상. 이해 후 구축.

**시스템의 3축** — ① 타임테이블 ② 역할 분담 ③ 트래킹 *(PjM이 관리)*

## 6개 직군 (재사용 — 모든 에이전시가 차출)

### 🏭 제공자 = 상품개발팀
| 직군 | 호출명 | 역할 | 주요 업무 |
|---|---|---|---|
| **PM** | `role-pm` | 제품 제작 총괄 책임자 | 제품 기획 · 구조 설계 · 팀 조율 · 일정 관리 |
| **MD** | `role-md` | 상품 기획자 | 상품기획 · 시장분석 · 생산수량 · 가격전략 · 판매전략 · 시즌 구성 |
| **Designer** | `role-designer` | 제품 경험의 시각화 | 로고 · 패키지 · 상세페이지 · 이벤트 |

### 📣 전달자 = 마케팅팀
| 직군 | 호출명 | 역할 | 주요 업무 |
|---|---|---|---|
| **Operator** | `role-operator` | 마케팅 운영 기획자 | 운영구조 · CTA(전환흐름) · CX 설계 · 카피 · DB분석 |
| **Marketer** | `role-marketer` | 마케터 | 전략 수립(시장·경쟁·타겟) · 캠페인 기획 · KPI 관리 |
| **PjM** | `role-pjm` | 진행 관리 책임자 | 일정 · 진행 · 캠페인 · 성과&리스크 조율 |

> **왜 사업체마다 복제하지 않는가**: 직군을 5개 사업에 복제하면 30명이 되지만 처리량은 늘지 않는다
> (직원 수 ≠ 처리량). OT의 **역할 분담** 원칙대로 **직군은 공용**, 에이전시가 필요할 때 **차출**한다.

**사업체별 1순위 직군**
- 창업이지 → **Operator**(양면 퍼널 전환) + **Marketer**(데일리 콘텐츠 유입)
- 하우스헬퍼 → **MD**(상품 구성·가격) + **Designer**(상세페이지)
- 아카데미 → **Marketer**(기수 모집) + PM(커리큘럼 구조)
- 넥스트헬퍼 → **PM**(제품 정의) → dev 체인 인계
- 라이프헬퍼 → **Operator**(예약 전환) — 나머지는 전담 10명이 커버

## 작업 체인 (산출물이 손에서 손으로)

```
[제공자]  role-pm ──→ role-md ──→ role-designer
          기획서      가격·구성     상세페이지
             │                          │
             └──────────┬───────────────┘
                        ▼
[전달자]  role-operator ──→ role-marketer ──→ (실행: ad-copy·shortform·blog-seo)
          전환 설계          캠페인 전략
                        │
                   role-pjm  ← 전 과정의 일정·트래킹·리스크
```

## 호출법
- 직군 직접: *"PM, 개업 패키지 제품 구조 설계해줘"* / *"MD, 열람권 가격 티어 다시 짜줘"*
- 사업 단위: *"하우스헬퍼 에이전시, 기획전 하나 만들어줘"* → 리드가 MD·Designer·Marketer 차출
