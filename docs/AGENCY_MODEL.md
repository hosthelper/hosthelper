# 🏢 헬퍼유니버스 에이전시 모델 (사업체별 AI 팀)

> 기능별 부서제를 넘어, **사업체마다 전담 AI 에이전시**를 두는 5단계(팀 에이전트) 조직.
> 참고 프레임: "AI 활용 6단계"(유호현) — 우리는 4단계(개인 에이전트)를 지나 **5단계(팀 에이전트)를 구현하는 중**이며,
> 6단계(Agent Internet)는 로드맵으로 남긴다. 자기개선 루프는 Hermes Agent(Nous Research) 아이디어의 경량 이식.

## 우리의 6단계 위치

| 단계 | 정의 | 우리 현황 |
|---|---|---|
| 1 검색형 | 질문·요약 | ✅ 일상 사용 |
| 2 생성형 | 초안·결과물 | ✅ 콘텐츠·기사·릴스 |
| 3 자동화형 | 반복 흐름 자동화 | ✅ 데일리 발행·자체점검 Routine |
| 4 개인 에이전트 | 목표 주고 위임 | ✅ 자율 실행 모드 |
| **5 팀 에이전트** | **팀 업무 구조에 AI 내장** | 🟡 **← 이 문서가 구현** |
| 6 Agent Internet | 에이전트끼리 연결·협상 | ⬜ 로드맵 (미래) |

### 에이전시별 편성

| 에이전시 | 리드 | 전담 | 본부 차출 | 핵심 KPI |
|---|---|---|---|---|
| 🏠 라이프헬퍼 | `agency-lifehelper` | CS 3·운영 4·성장 3 (10명) | 콘텐츠·데이터·법무 | 예약·가동률·정산·평점 |
| 🔑 창업이지·공실헬퍼 | `agency-changup` | changup-* 7명 | 콘텐츠·PII·법무 | 리드·검증등록·매칭·성사 |
| 🛒 하우스헬퍼 | `agency-house` | — (초기) | 카피·조사·가격 | 패키지 판매·재구매 |
| 📚 아카데미 | `agency-academy` | — (초기) | 콘텐츠·조사·운영 | 수강·완주·전환 |
| 🧭 넥스트헬퍼 | `agency-next` | — (AI 제품) | dev 스쿼드·조사 | 구독·갱신·검증률 |
| 🏛️ 본부 | 총괄실장 | 19명 | — | 에이전시 지원 SLA |

### 운영 규칙
1. **사업 관련 요청은 해당 에이전시 리드가 접수** → 분해·배정·취합 (리드가 없는 영역만 총괄실장 직접).
2. **본부 직원은 공용** — 에이전시가 차출하되, 충돌 시 총괄실장이 우선순위 조정.
3. **주간 리듬**: 각 리드가 KPI를 weekly-report에 인계 → 통합 현황판.
4. **사람 최종 확인** 원칙은 에이전시 단위에서도 동일(금전·법률·대외발송·계약).

## 🎯 직군 체계 (제로투원)

각 에이전시는 6개 직군을 **차출**해 일한다 — 제공자(**PM·MD·Designer**) / 전달자(**Operator·Marketer·PjM**).
사업체 × 직군 배치 매트릭스와 작업 체인은 **`docs/ZERO_TO_ONE.md`** 참고.

**시스템 3축**(대표 없이도 돌아가게 만드는 것): ① 타임테이블 ② 역할 분담 ③ 트래킹 — `role-pjm`이 관리하며,
특히 "**사람이 안 눌러서 멈춘 흐름**"을 정기 점검한다.

## 🔁 자기개선 루프 (Hermes 이식 · skill-evolve)

모든 에이전시는 작업 종료 시:
1. 회고 3줄(잘됨/막힘/다음) → 2. `TEAM_MEMORY.md` 기록 → 3. 막힌 원인이 스킬 문서에 있으면 **해당 SKILL.md 수정 커밋** → 4. 3회 반복 패턴은 본 문서 공통 규칙으로 승격.

> 스킬은 정적 문서가 아니라 **실전마다 자라는 자산**이다. (단, 문서 변경만 자율 — 코드·구조 변경은 dev 체인/대표 승인)

## 6단계(Agent Internet) 로드맵 메모
- 에이전시 간 연결의 첫 실험: 창업이지 리드 ↔ 라이프헬퍼 리드 간 "인수 고객 → 위탁 운영" 핸드오프 자동화.
- 외부 에이전트 연결(타사 서비스)은 privacy-guard 게이트 통과 후에만.
