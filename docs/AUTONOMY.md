# 🔄 대표 없이도 도는 시스템 (AUTONOMY)

> 질문: "대표가 없어도 돌아가는 시스템 구조로 설계하는 게 베스트겠지?"
> 답: **부분적으로만 맞습니다.** 전부 자동화하려다 아무것도 못 돌리는 게 1인 사업의 흔한 실패입니다.
> 목표는 "대표를 빼는 것"이 아니라 **대표가 눌러야만 하는 버튼의 개수를 줄이는 것**입니다.

## 먼저: 지금 구조의 정직한 진단

**현재 AI 직원 49명은 대표님이 말을 걸어야만 존재합니다.**
대표님이 대화를 시작하지 않으면 49명 전원이 정지합니다. 즉 **대표님이 유일한 시작 버튼**이고,
이건 "AI 직원을 고용했다"는 말과 실제로는 다릅니다. 늘려야 할 것은 직원 수가 아니라 **1층(사람 0)의 비율**입니다.

---

## 3층 구조

| 층 | 사람 개입 | 실행 주체 | 비용 | 예시 |
|---|---|---|---|---|
| **1층 · 완전 자동** | **0** | GitHub Actions cron | 무료·AI 크레딧 0 | 작업 현황 집계, 데일리 발행, 링크 점검, 주간 지표 |
| **2층 · 반자동** | **승인 O/X만** | AI가 초안 → 이슈/PR로 제출 | 초안 1회분 | 콘텐츠 초안, CS 답변안, 리포트, 코드 변경 |
| **3층 · 사람 전용** | **전부** | 대표님 | — | 낙찰가 결정, 계약 서명, 대외 발송, 방향 전환 |

### 설계 원칙
1. **판단이 필요 없는 일은 전부 1층으로 내린다.** 규칙으로 쓸 수 있으면 AI가 아니라 cron이 해야 합니다 (더 싸고 더 안 멈춤).
2. **2층 결과물은 "읽고 O/X" 크기여야 한다.** 대표님이 30초 안에 판단 못 하는 초안은 잘못 만든 것입니다.
3. **3층은 줄이지 않는다.** 돈·계약·법률·대외발송은 영구히 사람이 누릅니다 (`CLAUDE.md` 안전 원칙).
4. **막힌 것은 반드시 보이게 한다.** 자동화의 진짜 실패는 멈춘 걸 아무도 모르는 것입니다 → `board.html` 의 🚧 막힘 칸.

## 1층 현황 (지금 실제로 사람 없이 도는 것)

| 워크플로 | 주기 | 상태 |
|---|---|---|
| `status-snapshot.yml` — 작업 현황 집계 | 이벤트 즉시 + 3시간 | ✅ 신규 |
| `build-reel*.yml` — 릴스 제작 | 데일리 | ⚠️ 발행 단계 미검증 (PR #64) |
| `changup-content.yml` — 기사 발행 | 데일리 | ⏸️ 주제 재정의 대기 (창업이지 폐쇄) |
| `ci.yml` — 테스트 | 푸시마다 | ✅ |

> 1층이 늘어난 만큼만 대표님이 자유로워집니다. **이 표의 줄 수가 자율성의 실제 지표입니다.**

## 라이프헬퍼에서 1층으로 내려야 할 것 (우선순위)

매출 100%가 라이프헬퍼인데, 호스트가 **1명(대표님)** 입니다.
= 대표님이 2주 부재하면 매출이 0이 됩니다. 자동화 이전에 **위임**이 먼저입니다.

1. **체크인/청소/CS SOP 문서화** → 사람이 대신할 수 있게 (이슈 #70)
2. 예약·정산 알림 → 1층 자동화
3. 리뷰 수집·요약 → 1층 자동화

**주의**: SOP 없이 자동화부터 하면, 예외가 터졌을 때 아무도 대응 못 합니다.
순서는 **문서화 → 위임 → 자동화** 입니다.

## 작업 현황 파이프라인 (크레딧 0)

```
작업 카드 = GitHub 이슈
  라벨 상태:작업중 / 상태:막힘 / (없으면) 미작업
  라벨 사업:라이프헬퍼 · 사업:경매헬퍼 · 사업:본부 …
        │
        ▼
GitHub Actions  status-snapshot.yml     ← LLM 호출 없음 = AI 크레딧 0
  이슈·PR·커밋·워크플로 실행 결과를 집계
        │
        ▼
status.json  →  status-board 브랜치
        │
        ▼
Netlify (비번 보호)  →  board.html  ← 5분마다 스스로 재읽기
```

**왜 크레딧이 안 나가는가**: 집계에 AI를 쓰지 않기 때문입니다.
"몇 건인지 세는 일"에 언어모델은 필요 없습니다 — GitHub API + jq 로 충분합니다.
AI는 *판단*이 필요할 때만 부릅니다.
