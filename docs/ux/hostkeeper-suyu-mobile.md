# 호스트헬퍼 · 수유스테이 호스트키퍼 모바일 UI/UX 및 운영 기능 설계

작성: 2026-10-26
관리자 화면: /cleaning
청소 담당자 모바일 시안: /keeper

주의: 현재 프리뷰는 브라우저 로컬 저장 기반. 다른 기기 동기화, 직원 로그인, 사진 서버 업로드, 예약 달력 자동반영은 아직 구현되지 않았음. 실제 청소업체 투입 전 반드시 구현하고 검증할 것.

## 1. 목적과 역할
- 관리자: 청소 일정 생성, 담당자 배정, 진행현황, 완료 사진 검수, 승인·재작업 요청.
- 호스트키퍼: 자기에게 배정된 객실 목록, 마스터키 수령, 침구·객실·화장실·비품·시설 체크, 사진 제출, 완료 요청.
- 관리자는 기존 콘솔 유지. 호스트키퍼는 휴대폰 우선 3단계: 오늘 일정 / 청소 체크 / 완료 보고.

## 2. 객실별 자동 세팅
- 퀸 1개 2인실: 101,201,202,301,302,401,402,501.
- 슈퍼싱글 2개 4인실: 203,204,303,304,403,404.
- 2인실: 매트리스 커버 1, 이불 커버 1, 일반 베개 커버 2, 핑크 베개 커버 2, 생수 2.
- 4인실: 매트리스 커버 2, 이불 커버 2, 일반 베개 커버 4, 핑크 베개 커버 4, 생수 4.
- 화장실: 변기·세면대·샤워 공간·배수구·거울 청소, 휴지·샴푸·린스·바디워시 보충.
- 객실: 쓰레기 수거, 바닥·먼지·침대 아래·거울·냉장고 청소, 수건 및 시설 점검.
- 체크아웃 오전 11시 / 체크인 오후 4시. 청소 마감 목표 오후 3시 권장.

## 3. 현장 모바일 IA
1) 직원 로그인: 관리자 초대 후 전화 인증, 담당 숙소 지정, 사이트별 접근 제어.
2) 오늘 일정: 배정 객실, 작업 시작 시각, 다음 체크인, 작업 상태, 남은 객실, 긴급 작업.
3) 객실 상세: 큰 객실 번호, 객실 유형, 침구/생수 수량, 체크 항목과 진행률.
4) 사진 제출: 객실 전체·침구·화장실·세면대/배수·냉장고/생수 등 필수 5장, 파손 사진 추가.
5) 완료 보고: 체크·사진 검증 후 관리자 검수 요청. 직원은 직접 최종 승인하지 못함.
6) 근무 기록: 오늘/주간/월간 완료 수량과 재작업 이력.

## 4. 마스터키와 출입정보
- 공동현관 및 1층 집기실 출입번호는 소스 코드, 공개 페이지, 공유 CSV, 단체 문자, 프리뷰에 저장하거나 출력하지 않음.
- 인증된 배정 직원에게 근무 시간에만 별도 출입안내 노출, 서버 접근 감사 로그 필요.
- 객실 비밀번호로 출입하지 않음. 집기실의 마스터키 사용.
- 마스터키는 한 근무 회차에 수령 1번·모든 청소 종료 후 반납 1번 기록.
- 각 객실별로는 문 잠금만 검수. 키 반납을 객실마다 강제하지 않음.

## 5. 상태 머신과 예외
예정 -> 배정 확인 -> 청소 중 -> 완료 제출 -> 관리자 승인 -> 종료
- 사진 부족, 필수 체크 미완료 => 제출 차단.
- 관리자 불합격 => 재청소 요청 및 사유·사진 표시.
- 게스트 미퇴실, 예약 취소, 도어락 오류, 분실물, 시설 고장 => 별도 보고와 관리자 확인.
- 네트워크 끊김 => 미전송/대기 표시, 성공 응답 없이 완료 처리 금지.
- 변경자, 변경시각(KST 표시), 이전 상태, 재작업 이유를 서버에 기록.

## 6. 정식 데이터 모델 / 연동
기존 Prisma CleaningJob은 유료 청소거래 Booking에 연결되므로, 호텔 객실 하우스키핑 작업을 자동으로 결제·정산 생성하는 데 재사용하지 않음.
신규 엔터티 권고:
- HousekeepingSite / HousekeepingUnit (숙소와 14개 객실)
- HousekeepingTask (예약 체크아웃 참조, 날짜, 담당, 상태, 완료 시각)
- HousekeepingCheckResult (객실별 체크 이력)
- HousekeepingPhoto (비공개 사진 저장소 키와 업로드 메타데이터)
- HousekeepingShiftKeyEvent (근무 시작 수령/종료 반납)
- HousekeepingAuditLog (권한·출입정보 접근 및 상태 변경)
- HousekeepingReview (관리자 승인/재청소 요청)

관리자 및 호스트키퍼 간 작업 일정은 서버 DB 기반으로 실시간 동기화. 예약 캘린더 자동연동 전에는 수동 일정임을 명확히 표시. 자동 생성 시 체크아웃 예약 ID 기준 멱등 처리.

## 7. E2E 합격 기준
- 관리자 A가 203호를 배정하면 승인된 청소 담당자 B의 휴대폰에 즉시 표시.
- 다른 담당자 C는 해당 객실, 게스트 정보, 출입번호를 열람할 수 없음.
- 4인실 체크는 생수 4개 및 커버 2/2/4/4가 기본.
- 완료 사진 최소 5장을 서버에 업로드한 뒤에만 제출 성공 표시.
- 관리자 A의 승인·재청소 요청이 B에게 실시간 반영.
- 마스터키 수령·반납은 근무 1회에 1번씩 기록.
- 예약 취소·연장·객실 변경이 중복 일정이나 임의 출입을 만들지 않음.
- 사진 업로드 실패·오프라인·모바일 화면·수정 충돌에 대해 실제 사용자 시나리오 테스트 완료.

구현 단계: 1) 시연용 모바일 UI (/keeper) 2) 로그인/서버 DB/사진/관리자 검수/키 기록 3) 통합 예약 달력 연동 및 알림 자동화.
